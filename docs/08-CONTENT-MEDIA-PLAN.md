# Krishi Junction — Content & Media Plan

## 1. Important note on assets

We are building an **independent implementation** benchmarked against tractorjunction.com.
We do **not** copy their images, product photography, written copy, logos or database
content — that would be copyright and database-right infringement, and it would also
poison SEO with duplicate content.

Everything below is about sourcing our own assets.

## 2. Image inventory

| Asset | Count (v1) | Size / format | Source |
|---|---|---|---|
| Brand logos | 25 | SVG or 240×240 PNG, transparent | Official brand press kits / dealer-supplied, used nominatively for identification |
| Tractor model photos | ~60 models × 4–6 | 1600×1200 JPEG → WebP `detail/card/thumb` | Manufacturer press images (with permission), dealer photos, licensed stock, own photography |
| Implement photos | ~40 × 3 | 1200×900 | Same |
| Category icons | ~45 | SVG 48×48 | Custom icon set (Lucide/Phosphor base) |
| Home slider banners | 5–8 | 1920×640 desktop / 800×600 mobile | Designed in-house |
| Blog covers | per post | 1200×630 | Licensed stock (Unsplash/Pexels) or in-house |
| Placeholder / fallback | 1 per category | 800×600 | In-house illustration |
| Dealer photos | user-uploaded | max 2 MB, auto-resized | Dealers |
| Used-listing photos | user-uploaded | 4–12, max 5 MB each, EXIF stripped | Sellers |
| OG images | templated | 1200×630, auto-generated with model name | Generated by Browsershot |

**Prototype**: uses inline SVG illustrations and CSS gradients only — no third-party
images at all, so it can be shared safely.

## 3. Naming & storage

```
media/
├── brands/{brand-slug}/logo.svg
├── products/{brand-slug}/{model-slug}/{n}-{angle}.webp
├── implements/{brand-slug}/{model-slug}/{n}.webp
├── used/{year}/{month}/{listing-ref}/{n}.webp
├── dealers/{dealer-code}/{logo|photo-n}.webp
├── blog/{year}/{slug}-cover.webp
├── banners/{position}/{id}-{device}.webp
└── private/                       ← never web-readable
    ├── loan-docs/{application-ref}/{doc-type}.pdf
    └── dealer-docs/{dealer-code}/{doc-type}.pdf
```

Conversions generated on upload: `thumb` 300w, `card` 600w, `detail` 1200w, all WebP with
JPEG fallback, plus a 20px blurred LQIP placeholder.

## 5. Catalogue data

Per model we need: brand, name, category, HP, variants, ~40 spec values, ex-showroom
price (national + 10 states), 4–6 photos, brochure PDF, 2–3 videos, 3 competitors.

Fastest path: a Google Sheet with one row per model and one column per spec attribute →
imported via `php artisan catalog:import products.csv`. I will ship that importer plus the
sheet template in phase 2. Without client-supplied data, the demo seeder covers ~60 models
with representative (clearly marked as sample) values.
